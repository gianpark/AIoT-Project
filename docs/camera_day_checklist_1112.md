# 11/12 카메라 재사용일 체크리스트

논문 초안 마감(12/2)을 생각하면 촬영은 **하루(약 2~3시간)에 끝낸다.** 우선순위 순서대로 하고, 모자라면 뒤에서부터 버린다.
목적은 9주차 슬라이드의 약점을 데이터로 메우는 것이다: 참가자 3명(이번엔 늘릴 수 없음), 짧은 정상 녹화, p01 재촬영본의 구도 차이, 좌우 라벨 정의, 앱 실행 검증 미완료.
모델: `models/movenet_lightning_int8.tflite`. 모든 명령은 프로젝트 루트에서 가상환경을 켠 상태로 실행한다.

## 0. 시작 전 (10~15분)

- [ ] **촬영 가능 인원은 p01, p02 두 명뿐이다(새 참가자 없음).** 그래서 새 참가자 촬영(예전 §2)은 하지 않고, 두 사람의 데이터를 보강하는 데 쓴다.
- [ ] 카메라를 **환경 1(p02, p03을 찍은 구도)과 같은 자리·높이·각도**로 고정한다. 구도가 다르면 기존 7-class 데이터와 합칠 수 없다. 고정한 뒤 정상 자세로 5초 찍어 `data/_check.csv`로 몸통 길이 비를 확인한다(p02, p03은 1.05~1.14, 재촬영 p01은 0.71이라 합칠 수 없었다).
- [ ] `git pull`, `python -m pytest -q` (93개 통과가 정상).
- [ ] 촬영 동의 확인. 사진과 `data/snaps/`는 git에 올리지 않는다.

- [ ] **p03은 추가 촬영을 하지 않을 수 있다.** 이번 촬영분(긴 정상 녹화, 손 동작, 좌우 재촬영, p01 v4)에는 p03이 없으므로, 새 데이터로 계산한 오경고율·좌우 결과는 **p01, p02 두 명 기준으로 따로 보고**하고 3명 결과와 섞지 않는다. 기존 p03 로그는 7-class 분석에 그대로 쓴다.

## 0-1. RGB·Depth 원본 저장과 IRB 승인 시점 (촬영 전에 정한다)

IRB 계획서에 "RGB·Depth 원본을 저장해 다른 팀에 제공한다"고 적었으므로, 촬영 명령에 `--save-raw`를 붙여 원본을 같이 저장한다(카운트다운 구간은 저장되지 않음).
```
... --countdown 5 --duration 20 --save-raw data/raw_rgbd/<참가자>/<자세>
```
- [ ] **시작 전 5초 시험**: `--duration 5 --save-raw data/raw_rgbd/_test/t1`로 돌려 `color/`, `depth/`, `frames.csv`, `meta.json`이 생기는지, FPS(약 30)가 떨어지지 않는지 본다. 되면 `_test` 폴더는 지운다.
- [ ] **저장 공간**: 자세 1개(20초)에 약 150~200MB, 11종 한 세트에 약 2GB. 정상 5분 녹화는 약 2.5GB로 따로 잡는다. 두 사람 합쳐 15GB 이상 비워 둔다.
- [ ] `data/raw_rgbd/`는 얼굴이 들어간 원본이라 git에 올리지 않는다(`.gitignore`에 등록함).
- **결정(11/11): 분석에는 IRB 승인 후 서면동의를 받아 새로 찍은 자료만 쓴다.** 그래서 내일 촬영분은 앱 실행 검증과 `--save-raw` 시험 등 시험용이고, 타 팀 제공과 IRB 연구의 분석에는 쓰지 않는다. 얼굴 원본은 시험 후 삭제하거나 제공 대상에서 제외한다. 공유용 tilt(P3, P4)와 제공용 원본은 승인 후 서면동의를 받고 다시 촬영한다.
- 승인 후 촬영에서는 서면동의서(촬영 동의와 타 팀 제공 동의를 따로 체크)를 받고, 사본을 종이 복사 또는 사진으로 그 자리에서 참가자에게 준다.

## 1. 앱 실행 검증 (15분, 가장 먼저)

주의 알림과 턱 우선 규칙은 단위 테스트만 통과했고 카메라로 돌려 본 적이 없다.
```
python -m src.pose.movenet_keypoints --model models/movenet_lightning_int8.tflite --realsense --judge --caution-alert --log data/_app_check.csv
```
- [ ] 정상 자세 1분: 알림이 울리지 않아야 한다.
- [ ] 거북목, 앞으로 숙이기, 턱 괴기를 각 1~2분: 경고 또는 주의 알림이 나오는지, 턱 괴기가 chin으로 표시되는지 본다.
- [ ] 알림이 뜬 시각과 종류를 기록란에 적는다(슬라이드 13의 "실행 검증 미완료"를 지울 근거).

## 2. 정상 자세 보강 (p01, p02 모두, 사람당 20분)

- [ ] **정상 자세 5분 이상 한 파일**(`..._normal_long.csv`): 몸을 조금씩 움직이고 자세를 고쳐 앉는 동작을 넣는다. 오경고율을 처음으로 제대로 잴 수 있다.
- [ ] **손을 얼굴로 가져가는 정상 동작**(`..._normal_hands.csv`, 20초×2회): 코 만지기, 안경 고치기, 머리 넘기기. 손목 점수 기준(현재 0.3)의 오경고 영향을 검증하지 못했던 부분이다.
- [ ] 세션 보정 가정 확인: 시작 5초 뒤에 앉는 위치를 바꾼 녹화 1개(`..._normal_shift.csv`). 가슴 규칙이 보류된 이유(앉는 위치 변화)를 확인한다.

## 3. p01 재촬영 (구도를 환경 1에 맞춰서, 15분)

기존 `data/side_p01_v3`에는 normal, neck_light, neck_hard, forward 4개뿐이다. 나머지 자세를 같은 구도로 채우면 p01을 p02, p03과 합칠 수 있다.
- [ ] 자세 11종 20초씩, 파일은 `data/side_p01_v4/`에 둔다(v3를 덮어쓰지 않는다). 명령은 `--log data/side_p01_v4/side_p01_<자세>.csv --countdown 5 --duration 20 --snap-every 2`, 자세 목록은 `docs/side_capture_plan.md`.
- 이 촬영이 성공하면 p01이 p02, p03과 같은 구도가 되어 선우 님의 7-class 수치와 이어 붙일 수 있다(참가자 수는 3명 그대로).

## 4. 좌우 기울임 (p01, p02, 사람당 약 20분)

다른 조와 데이터를 공유하려고 공통 자세 코드를 쓴다: P0 정상, P1 거북목, P2 상체 후방, P3 좌측 기울임, P4 우측 기울임, P5 전방.
우리 `left_lean_neck`, `right_lean_neck`는 "옆으로 기대면서 고개를 내미는" 자세라 순수한 좌우 기울임(P3, P4)과 다르다. 그래서 **두 가지를 나눠 찍는다.**
라벨마다 목 내민 정도가 달랐던 문제(0.215 m, 0.12~0.13 m, 0.14~0.17 m)를 막으려고 정의를 먼저 적고 시작한다.

- [ ] **촬영 전에 다른 조와 확인해 한 줄로 기록**: ① 목은 내밀지 않는다 ② 기울기 크기(어깨선이 보일 정도로 확실히 / 약하게도 포함) ③ 상체 전체를 기울이는지, 고개만 갸웃하는지. 기록란에 그대로 적는다.
- [ ] **공유용(P3, P4)**: 목은 내밀지 않고 상체만 옆으로 기울임. `left`, `right` 각 20초 × 2회, 기울기가 약한 것과 큰 것을 구분해 찍는다(기준값 0.35를 낮춰도 되는지 보려면 약한 기울임 데이터가 필요하다). 파일명 예: `side_<참가자>_tilt_left.csv`, `side_<참가자>_tilt_right.csv`.
- [ ] **기존용**: 옆으로 기대면서 고개 내밈, 기존 `left_lean_neck`, `right_lean_neck`와 같은 정의로 각 20초 × 2회. p02는 환경 1에 이미 있으니 정의가 일관되는지 본다.
- [ ] 공유용 파일만 다른 조에 넘긴다. 기존 `left_lean_neck` 로그는 우리 분석에만 쓴다(목 내밈이 섞여 P3, P4와 다르다).

### 공통 자세 코드 대응표

| 공통 코드 | 우리 클래스 | 우리 녹화 라벨 | 비고 |
|---|---|---|---|
| P0 정상 | normal | normal | 그대로 |
| P1 거북목 | turtle_neck | neck_light, neck_hard | 약함·강함 합침, 공유 파일에 원래 라벨 열을 같이 둔다 |
| P2 상체 후방 | lean_back | back_light, back_hard | 약함·강함 합침, 원래 라벨 열을 같이 둔다 |
| P3 좌측 기울임 | left_lean | 새로 찍는 tilt_left | 기존 left_lean_neck는 제외 |
| P4 우측 기울임 | right_lean | 새로 찍는 tilt_right | 기존 right_lean_neck는 제외 |
| P5 전방 | forward | forward | 그대로 |

bad_posture(back_neck, chin, slouch)는 공통 6개에 없으므로 공유본에서 뺀다. 우리 7-class 결과와 섞지 않도록 공유본은 6-class로 따로 이름 붙인다.
공유 형식(로그 CSV인지 사진인지)과 IRB 범위는 공유 전에 확인한다. 사진만 주면 우리 깊이 특징은 쓸 수 없다.
