## 3.1 시스템 개요

책상 앞 작업자를 측면에서 보는 Intel RealSense D455(RGB + 스테레오 깊이)의 한 프레임에서 (1) MoveNet Lightning int8(CPU)로 17개 keypoint를 얻고, (2) 같은 시점의 depth 프레임에서 머리·가슴·허리의 거리를 읽어 (3) 머리–가슴·허리–가슴 depth 차와 각도 특징을 만들고, (4) 경고 임계 대비 비율로 자세(정상/주의/경고)와 화면 근접을 따로 판정한 뒤 OR로 결합하여, (5) 알림 상태머신이 연속성과 쿨다운을 적용해 알림을 낸다. 5초 주기로 샘플링하므로 프레임마다 모든 처리를 하지 않는다. 모든 처리는 CPU만 쓴다.

## 3.2 깊이 정렬과 전처리

- RGB와 depth를 정렬(align)한 뒤 SDK 기본 필터에 홀 필링 "nearest"(mode 2)를 적용한다. 기본 홀 필링은 먼 값으로 채워 얼굴이 배경으로 마스킹되는 문제가 있어 바꿨다(깊이 필터 7개 설정 비교, D2).
- depth 범위 마스크와 9×9 닫힘 연산으로 전경(사용자)을 분리하고 사용자를 자동으로 인식한다.

## 3.3 Depth 기반 자세 특징

| 특징 | 정의 | 비고 |
|---|---|---|
| 머리 depth | 코 픽셀의 depth | 얼굴 끝을 머리로 사용(귀는 위치가 불안정, 눈은 기울면 좌우가 달라짐) |
| 가슴 depth | 어깨 중점 아래 0.25·0.5 어깨너비 두 점과 양 어깨, 4점의 **중앙값** | 앞으로 내민 얼굴·턱이 어깨 중점을 가려 값이 튀는 문제를 제거. 유효 점이 2개 미만이면 어깨 중점으로 대체 |
| 허리 depth | 엉덩이 점수 ≥ 0.5일 때만 사용 | 책상에 가려진 엉덩이의 추측 위치는 depth가 오염됨 |
| 목 전방 오프셋 | 가슴 depth − 머리 depth (m) | 클수록 고개를 앞으로 내민 상태 |
| 몸통 기댐 오프셋 | 허리 depth − 가슴 depth (m) | 양수 = 숙임, 음수 = 기댐 |
| 머리 전방 각도 | 측면 뷰에서 가슴→머리 선이 수직선에서 카메라 쪽으로 기운 각도(°) | `head_forward_deg`. 카메라가 내려다보는 각도만큼 틀어지므로 절대값이 아니라 상대 비교용(IMU 중력 보정은 설계만 있고 미연결) |
| 손목–얼굴 거리 | 코에서 가까운 손목까지 / 어깨너비 | 턱 괴기 신호 |
| 머리 높이, 몸통 길이비 | 측면 뷰의 머리 높이(m), 몸통 길이 / 어깨너비 | 보조 특징 |

측면 뷰는 가로축을 depth, 세로축을 높이(어깨너비 0.40 m 가정으로 환산)로 그려 사람이 직접 확인할 수 있게 한다(머리 원 반지름 0.11 m, 가슴→머리 목 선, 팔, 정상 기준 점선). EMA(α=0.2)와 15프레임 유지 평활로 깜박임을 줄였다.

## 3.4 규칙 기반 판정

자세 종류마다 "경고 임계 대비 비율"을 계산하고, 비율 ≥ 1이면 경고, ≥ 0.7이면 주의로 한다. 여러 종류가 동시에 0.7 이상이면 복합 자세로 보고 가장 높은 것을 대표 종류로 쓴다.

| 종류 | 신호 | 경고 임계(잠정) | 비고 |
|---|---|---|---|
| 기댐(slouch_back) | 목 오프셋 ≤ 0.10 m (0.13 m부터 선형) | 가슴 depth ≥ 0.55 m이고 근접 아닐 때만 | 앞숙임 때도 오프셋이 줄어 구분 필요 |
| 고개 내밈(neck_forward) | 목 오프셋 ≥ 0.18 m (0.15 m부터 선형) | | |
| 턱 괴기(chin_rest) | 손목–얼굴 ≤ 0.65 어깨너비 (1.2부터 선형) | | |
| 근접 | 머리 또는 가슴 depth < 0.40 m | 얼굴 depth가 무효(센서 최소 거리 안쪽)여도 근접으로 처리 | 자세 판정과 OR 결합 |
| 좌우 기울임 | 어깨 중점의 엉덩이 중점 대비 가로 치우침 ≥ 0.35 어깨너비 | 몸통만 본다(머리만 기울인 경우 제외) | |

임계값은 참가자 2명의 로그에서 정한 **잠정값**이다. T4의 ROC 분석에서 현재 경고 기준의 특이도는 1.00이었고, 최적값으로 낮추면 참가자 교차 평가에서 특이도가 0.67~0.72로 떨어져 유지했다. 사람 간 차이가 커서(머리 각도 12.0° 대 회차 간 2.9°) 개인 보정이 후속 과제다.

## 3.5 알림 상태머신

- 근접: 감지 즉시 1회 알림, 이후 60초 쿨다운.
- 자세: 5초 샘플링에서 경고가 연속 3회(약 15초 지속, 첫 알림 시점은 3번째 샘플) 나오면 알림, 이후 300초 쿨다운. 주의 단계는 연속 횟수에 세지 않고, 경고가 끊기면 연속 횟수를 리셋한다. 근접과 자세의 쿨다운은 서로 독립이다.
- 오프라인 시나리오 9개로 최소 간격(≥ 60 s, ≥ 300 s)을 단언문으로 검증했다(`tests/test_alert_scenarios.py`).

## 3.6 학습 기반 분류기 (비교용)

Random Forest(300그루, class_weight=balanced)에 depth·각도 특징과 결측 플래그를 입력한다. 결측은 학습 데이터 중앙값으로 대치하고 결측 여부를 이진 특징으로 함께 준다. 평가는 참가자 단위 교차검증만 사용한다. 다른 분류기는 7주차 공정비교에서 추가한다.

## 3.7 MoveNet 수정

교수님의 "MoveNet을 그대로 쓰지 말고 수정하라"는 지침을, 학습 없이 CPU에서 돌아가는 **파이프라인 수정**으로 구현하기로 팀이 판단했다(공식 학습 코드가 없어 가중치 재학습은 비용이 크고, 우리 시스템의 강점이 깊이 결합이기 때문). 가중치 재학습(Thunder→Lightning 증류)은 시간이 남을 때의 선택 과제로 둔다.

- **(D) 입력단 ROI 크롭** `src/pose/roi_crop.py`, `--roi-crop`: 직전 프레임의 유효 keypoint bbox(+30% 여백)를 정사각형으로 잘라 모델에 넣고 좌표를 원본 프레임으로 되돌린다. 사용자가 작게 보일 때 192×192 입력 안의 해상도를 높이는 것이 목적이다. 30프레임마다, 또는 유효 점이 4개 미만이면 전체 프레임으로 되돌아가 사용자를 다시 찾는다. 학습이 필요 없고 모델은 그대로다. 효과(키포인트 점수·결측·판정 성능, 추론 시간)는 측정 전이다. `[ ]`
- **(A) 깊이 기반 keypoint 보정** (구현 예정): 점수가 낮거나 가려진 코·어깨·손목을 depth(전경 마스크, 이전 프레임 위치)로 복원한다. 현재 손목 결측이 약 40%, 엉덩이 depth 결측이 약 69%라 효과가 클 것으로 예상하지만 검증 전이다. `[ ]`
- 두 방법 모두 4.5 ablation에 "수정 전/후" 행으로 넣는다. 로그에 keypoint x/y가 기록되도록 바꿨으므로(10/14) 같은 자세를 `--roi-crop` 켜고/끄고 재촬영하면 점수·결측률·판정 성능을 직접 비교할 수 있다.
