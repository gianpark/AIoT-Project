### 4.2 Implementation setup

- **하드웨어**: Intel RealSense D455(스테레오 베이스라인 95mm, RGB 동기), 사용자 노트북·데스크톱 CPU 전용. `[CPU 모델, RAM, OS 기재]` ❌
- **포즈 추정**: MoveNet Lightning int8 TFLite, 17 keypoint. `[파라미터 수, 입력 해상도 기재]` ❌
- **깊이 처리**: SDK 기본 필터 + 홀 필링 "nearest"(mode 2). 근거는 D2 (SDK 기본은 먼 값으로 채워 얼굴이 마스킹됨, 필터 없음은 유효 비율이 낮음). ✅
- **전경 분리**: depth 범위 마스크 + 9×9 닫힘 연산, 사용자 자동 인식(ROI). ✅
- **특징 정의**: 머리(코), 가슴(어깨 아래 4점 중앙값), 허리(엉덩이 점수 ≥ 0.5일 때만). 머리–가슴 depth 차, 허리–가슴 depth 차, 손목–얼굴 거리/어깨너비, 측면 각도. ✅
- **판정·알림**: 경고 임계 대비 비율로 주의(70%)/경고, 샘플 주기 5초, 근접 즉시 1회 후 60초, 자세 연속 3회 후 300초 쿨다운. ✅ (`src/logic/decision.py`)
- **소프트웨어 환경**: Python, OpenCV 4.13, TensorFlow, scikit-learn 1.8 (`requirements.txt`). ✅

### 4.3 Results on depth measurement accuracy

참고 논문의 "SOTA 비교표" 자리. 우리는 깊이 센서를 직접 쓰므로 **센서 정확도와 거리별 경향**을 보인다.

| 거리대 | 반복 | 평균 오차(%) | 최대 오차(%) |
|---|---|---|---|
| ~37cm | 3 | 0.54 | 0.82 |
| ~55cm | 2 | 0.54 | 0.54 |
| ~74cm | 2 | 1.29 | 1.49 |
| ~92cm | 2 | 1.41 | 1.63 |

- 해석: 책상 사용 거리(37~92cm)에서 오차 1.63% 이하, 거리가 멀수록 오차 증가. ✅
- 추가할 것: 근접 사각지대(< 약 0.3m)에서 depth 무효가 되는 구간과 "얼굴 depth 무효 = 근접" 규칙의 근거 그림. ⚠️ (40cm 이하 정량 검증은 카메라 필요 ❌)

### 4.5-2 Cross-environment generalization and session calibration (D7)

- **문제**: 기존 환경(D4)에서 학습한 RF를 새 환경(D7)에 적용하면 성능이 무너진다. 같은 사람의 normal 자세도 `head_forward_deg` 약 10~12° 감소, `neck_forward_offset_m` 0.14→0.10, `chest_depth_m` 0.70→0.62로 이동한다(카메라 위치·앉은 거리 차이). `[experiments/rf_cross_env.md]`
- **결과(no_hip, Macro-F1)**: 기존 환경 내 LOPO 0.667(9클래스)/0.731(7클래스) → 기존 전원으로 학습해 새 환경 평가(환경만 새것, S1) 0.18/0.27~0.36, 해당 사람 제외(사람·환경 새것, S2) 0.17~0.45/0.25~0.45. 대부분의 자세가 back_hard나 normal로 쏠린다.
- **세션 시작 normal 보정**(세션별 normal 첫 N초의 중앙값을 특징에서 뺌, 보정에 쓴 프레임은 학습·평가에서 제외): 7클래스 S1 0.317→0.641, S2 0.306→0.491, env1 LOPO 0.747→0.777 (100그루 RF). 9클래스 S1 0.178→0.530, S2 0.236→0.361. `[experiments/rf_calib_study.md]`
- **설계 비교**: 구간 3초(0.658)/5초(0.641)/10초(0.607)는 차이가 작고 세션 전체 사용은 약간 낮다 → 시작 시 3~5초면 충분. 거리 계열만(0.455)·각도 계열만(0.325) 보정보다 전체 보정이 낫다. MAD 나눔 정규화는 오히려 나쁘다(0.334). 회차를 세션으로 나누지 않고 한 번만 보정하면 LOPO가 0.27로 붕괴 → **세션(앉을 때)마다 재보정이 필요**.
- **해석 주의**: 새 환경은 2명·자세당 1회, 설계 선택과 평가를 같은 데이터로 해서 낙관적일 수 있다. 사람·환경 모두 새것(S2)은 0.49로 여전히 기존 환경 내(0.78)보다 낮다. `back_neck`, `slouch`는 두 시나리오 모두 recall 0%.
- **논문 연결**: (1) 현재 0.667/0.731은 "같은 환경 안에서의 사람 간 일반화"로 한정해 서술, (2) 세션 시작 보정을 시스템 설계로 제시하고 데이터로 뒷받침, (3) 교수님 질문("매번 기준점을 잡아야 하나")에 대한 답 근거. 참가자 추가 시 재검증 필요.

### 4.5-3 Side-view estimate vs. photo reference (D8)

- **방법**: 휴대폰으로 옆에서 찍은 사진에 MoveNet Thunder를 돌려 코·귀·어깨 점을 잡고, 어깨→코 선이 수직선과 이루는 각도(보는 방향이 +)를 계산(`scripts/photo_gt_angles.py`). 점 표시 이미지로 10장 모두 점이 코·귀·어깨에 맞게 찍힌 것을 눈으로 확인. 같은 자세의 새 환경 로그(`side_env2`)에서 `head_forward_deg` 중앙값을 뽑아 비교.
- **결과(10점: 2명 × 5자세)**: 사진 각도 대 `head_forward_deg` 순위상관 0.87(p=0.001), 참가자별로 각각 0.90. 귀-어깨 각도와는 0.89. 자세 순서는 두 값에서 일치(normal < neck_light < neck_hard, back_hard 최소). 사진 각도 대 `neck_forward_offset_m`도 0.86.
- **예외·해석 주의**: (1) forward는 사진 각도가 neck_light보다 작은데 로그 값은 더 크다. 로그는 가슴→머리 선, 사진은 어깨→코 선이라 정의가 달라서이며, 절대 일치가 아니라 **순서와 방향 일치**로 서술한다. (2) p02는 normal(45.0°)과 neck_light(41.5°)가 사진·로그 모두 비슷해(로그 21.5° vs 22.9°) 약한 거북목은 구분이 약하다. (3) 10점(2명)이고 사진 각도는 모델 점 기반이라 몇 도 흔들릴 수 있다. 방향 확인용이며 정밀 검증이 아니다. (4) 촬영 순서가 참가자마다 달랐고 자세 이름은 촬영자가 기억으로 붙였다.
- **논문 연결**: "카메라 한 대로 만든 측면 값이 실제 옆모습과 같은 방향으로 움직인다"는 기여 2·3번의 예비 근거. 참가자를 늘리고 자세를 더 촬영해 상관의 신뢰구간을 보고하면 주장이 단단해진다.
- **데이터 취급**: 사진에는 얼굴이 나오므로 저장소·논문에는 숫자만 쓴다. 그림으로 쓰려면 동의 확인과 가림 처리 필요.

### 4.6 Case study analysis

참고 논문의 관절별 오차 비교 자리. 자세·신호별로 무엇이 되고 무엇이 안 되는지를 분석한다.

- **재현성**: 같은 사람 내 회차 간 변동 대 사람 간 변동 (머리–가슴 차 회차 간 ±0.02, 자세 안 변동 ±0.01). ✅ T1
- **참가자 차이**: 절대 거리는 사람마다 다르다(normal 머리 depth 0.51m 대 0.64m)는 점 → 상대값(차이, 각도, 어깨너비 정규화)을 써야 하는 근거. ✅
- **성공 사례**: 턱 괴기(손목–얼굴 0.4 대 1.1 이상으로 분리), 기댐과 고개 내밈의 분리. ✅
- **실패 사례** (한계로 정직하게 제시): ✅
  1. 책상에 가려진 엉덩이 → 추측된 점의 depth 오염(p01은 엉덩이 depth 유효율 0~17%).
  2. slouch와 neck_hard: 목 오프셋 임계값 약 0.20에서 교차 민감도 0.80/1.0, 특이도 0.95/0.96으로 **정도 차이로는** 갈리지만(0.188 대 0.219) RF에서는 서로 크게 혼동(slouch 재현율 20~71%). 종류가 아니라 강도 차이로 서술.
  3. back_neck(뒤로 기대며 고개 내밈)는 두 효과가 상쇄돼 머리–가슴 차가 normal과 같음(AUC 0.54). 대신 `head_up_m`(AUC 1.0, 0.151 대 0.203)과 `head_forward_deg`(0.999, 42.6° 대 33.8°)로 구분된다(T4, 참가자 교차 민감도 0.97~1.0).
  4. 강도("살짝/많이")의 개인·회차 차이(neck_light 중앙값 0.21 대 0.16).
- **재현성 수치 (T1, 자세별 회차 중앙값의 절대차 중앙값)** ✅

- 분류기 단계의 크기·시간은 이미 측정됨(Table D): 50그루 RF는 약 1.5~2.2MB, 샘플당 1.6~3.0ms(scikit-learn 단일 호출 기준). 이 값은 파이프라인 전체의 일부일 뿐이며 MoveNet 추론과 깊이 처리를 포함한 전체 측정이 필요하다. ⚠️
- 비교 맥락으로 참고 논문 Table 4의 값을 인용한다(RTX 4090 기준, 2D 검출기 제외, lifting 단계만): VideoPose3D 16.9M params/33M FLOPs/863 FPS, PoseFormer 9.6M/1358M/269, P-STMO 6.2M/1350M/3040, FGPDFormer 5.9M/625M/3380. **조건이 달라(GPU, lifting만 측정) 직접 비교하지 않고 "상용 노트북 CPU에서 전체 파이프라인을 돌린다"는 점을 강조**한다.
- 측정 방법: 5초 샘플링 대 프레임마다 처리했을 때의 CPU·RAM, 게임 부하 동시 실행 시 영향. 카메라 없이 가능한 부분(모델만, 녹화 프레임 재생)과 카메라가 필요한 부분(전체 파이프라인) 구분. ⚠️/❌

### 4.9 Limitations and threats to validity

- 참가자 3명(x/y 좌표 열이 있는 로그는 2명), 자세당 1~3회: 일반화 주장은 하지 않고 "가능성 확인"으로 서술. 참가자 확대가 우선 과제. 같은 촬영의 프레임은 서로 매우 비슷해 프레임 단위 지표는 부풀려지고 신뢰구간이 없다.
- MoveNet 수정(D, A)의 평가는 같은 프레임 비교이지만 참가자 3명·자세당 1~3회이며 정답이 없어, 경고가 늘어난 것이 정확도 향상인지 민감도 증가인지 구분하지 못한다. 깊이 보정(A)은 이 환경에서 효과를 확인하지 못했다.
- 2D 기준선이 x/y 열이 있는 2명 분량뿐이라 "깊이 융합이 2D보다 낫다"는 주장은 하지 않는다.
- 절대 깊이(앉는 거리)에 의존하는 분류 성능 하락(0.667 → 0.551)은 카메라 위치가 달라지는 환경에서의 위험이다. 실제로 새 환경(D7)에서는 보정 없이 0.2~0.4대로 떨어졌고(4.5-2), 세션 시작 보정으로 부분 회복(7클래스 0.32→0.64)했지만 사람·환경이 모두 새로운 경우는 0.49에 그쳤다. 새 환경은 2명·자세당 1회 촬영이다.
- 단일 카메라 위치·각도, 단일 책상·의자 환경. 중력 보정(IMU)은 설계만 있고 판정에 미연결.
- 라벨 신뢰성: 사진 라벨은 팀원 간 교차 라벨링에서 불일치 사례가 있었다(rl_035). 로그 라벨은 "지시한 자세"이며 사람이 실제로 얼마나 일관되게 취했는지는 사진으로 샘플 확인했다. `[샘플 확인 결과]` ❌
- 정답 3D 좌표(모션캡처)가 없어 MPJPE로 평가할 수 없다. 대신 줄자 실측(깊이)과 분류 정확도로 평가한다. 측면 값은 옆에서 찍은 사진의 코·어깨 각도와 순서만 비교했고(2명·10점, 4.5-3) 각도 값 자체의 일치는 검증하지 못했다.
- 근접 40cm 이하와 좌우 기울임은 아직 정량 검증 전.
